## 1. DDL – Data Definition Language

Used to **create, change, or delete** database structures.

| Keyword  | Purpose                                                     |
| -------- | ----------------------------------------------------------- |

| DROP     | Delete objects                                              |
| TRUNCATE | Remove all rows quickly (cannot be rolled back in some DBs) |
| RENAME   | Rename a table                                              |

## 4. DCL – Data Control Language

Used for **permissions and security**.

| Keyword | Purpose            |
| ------- | ------------------ |
| GRANT   | Give user access   |
| REVOKE  | Remove user access |

# Data Control Language (DCL)

DCL is used to control who can access the data in a database.
It has two commands: GRANT and REVOKE.

---

## GRANT

Used to give permission to a user.

```sql
GRANT SELECT ON company.employees TO 'alice'@'localhost';
```

This allows `alice` to read data from the `employees` table.

---

## REVOKE

Used to take back a permission from a user.

```sql
REVOKE SELECT ON company.employees FROM 'alice'@'localhost';
```

This removes `alice`'s ability to read from the `employees` table.

---

## Common Privileges

| Privilege | What it allows        |
|-----------|-----------------------|
| SELECT    | Read data             |
| INSERT    | Add new rows          |
| UPDATE    | Edit existing rows    |
| DELETE    | Remove rows           |
| ALL       | All of the above      |

---

## Simple Example

```sql
-- Create a user
CREATE USER 'john'@'localhost' IDENTIFIED BY 'password123';

-- Give permission to read and insert
GRANT SELECT, INSERT ON company.* TO 'john'@'localhost';

-- Remove insert permission later
REVOKE INSERT ON company.* FROM 'john'@'localhost';
```

---

## Key Points

- GRANT gives access, REVOKE takes it away.
- Always give users only the permissions they actually need.
- Use `FLUSH PRIVILEGES;` after changes in older MySQL versions.

## 5. TCL – Transaction Control Language

Used to manage **transactions**.

| Keyword         | Purpose                                   |
| --------------- | ----------------------------------------- |
| COMMIT          | Save all changes permanently              |
| ROLLBACK        | Undo changes made in a transaction        |
| SAVEPOINT       | Create a checkpoint to rollback partially |
| SET TRANSACTION | Define transaction settings               |

**Step 5: TCL — Transactions (COMMIT, ROLLBACK)**

Using transactions to ensure data safety.


### Task 3: DCL & TCL — Access Control & Transactions (Challenge)
**Objective**: Practice user permissions and safe transactions.

1. Create user `teacher1` with password.
2. Grant SELECT and INSERT on `school_db.students`.
3. Revoke INSERT permission.
4. Start a transaction: insert 2 students → SAVEPOINT → insert 1 more → ROLLBACK TO SAVEPOINT → COMMIT.
5. Verify only first 2 students are saved.

**Expected SQL**:
```sql
CREATE USER 'teacher1'@'localhost' IDENTIFIED BY 'pass123';
GRANT SELECT, INSERT ON school_db.students TO 'teacher1'@'localhost';
REVOKE INSERT ON school_db.students FROM 'teacher1'@'localhost';

START TRANSACTION;
INSERT INTO students (name, age, city) VALUES ('Ravi', 16, 'Salem');
INSERT INTO students (name, age, city) VALUES ('Maya', 15, 'Trichy');
SAVEPOINT sp1;
INSERT INTO students (name, age, city) VALUES ('Deva', 17, 'Madurai');
ROLLBACK TO sp1;
COMMIT;
```
