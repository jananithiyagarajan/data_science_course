# SQL Views

## What is a VIEW in SQL?

In SQL, a **VIEW** is a virtual table based on the result of a stored SELECT query.
It does not store data physically; instead, it dynamically fetches data from the underlying tables whenever queried.

### Key Properties
- Is a **named SQL query**
- Acts like a table for SELECT operations
- Improves **security**, **simplicity**, and **reusability**
- Can hide complex joins and sensitive columns

---

## Basic View Syntax

```sql
CREATE VIEW view_name AS
SELECT column1, column2, ...
FROM table_name
WHERE condition;
```

## Creating and Using Views

### Example 1: IT Department View

```sql
CREATE VIEW vw_it_employees AS
SELECT emp_name, salary, city
FROM employees
WHERE department = 'IT';

-- Query the view
SELECT * FROM vw_it_employees;
```

### Example 2: Department Summary View

```sql
CREATE VIEW vw_dept_summary AS
SELECT department,
       COUNT(*) AS emp_count,
       AVG(salary) AS avg_salary,
       MAX(salary) AS max_salary,
       MIN(salary) AS min_salary
FROM employees
GROUP BY department;

SELECT * FROM vw_dept_summary ORDER BY avg_salary DESC;
```

### Example 3: High Earners View (Security)

```sql
-- Hide salary from basic users, only show name and dept
CREATE VIEW vw_public_employees AS
SELECT emp_name, department, city
FROM employees;

-- Only authorized users can see the salary view
CREATE VIEW vw_salary_report AS
SELECT emp_name, department, salary
FROM employees
WHERE salary > 50000;
```

### Example 4: View with JOIN

```sql
CREATE VIEW vw_employee_projects AS
SELECT e.emp_name, e.department, p.project_name, p.status
FROM employees e
INNER JOIN projects p ON e.emp_id = p.lead_emp_id;

SELECT * FROM vw_employee_projects;
```

## Managing Views

### Replace/Update a View

```sql
CREATE OR REPLACE VIEW vw_it_employees AS
SELECT emp_name, salary, city, department
FROM employees
WHERE department = 'IT'
ORDER BY salary DESC;
```

### Drop a View

```sql
DROP VIEW IF EXISTS vw_it_employees;
DROP VIEW vw_dept_summary;
```

### Check Existing Views

```sql
SHOW FULL TABLES WHERE TABLE_TYPE = 'VIEW';
DESCRIBE vw_dept_summary;
```

## Updatable Views

Some simple views are updatable (INSERT/UPDATE/DELETE on view modifies base table).

```sql
-- Updatable view (no GROUP BY, DISTINCT, aggregate functions)
CREATE VIEW vw_chennai_employees AS
SELECT emp_id, emp_name, salary
FROM employees
WHERE city = 'Chennai';

-- Update through view
UPDATE vw_chennai_employees
SET salary = salary * 1.1
WHERE emp_name = 'Arun';

-- Verify
SELECT * FROM employees WHERE city = 'Chennai';
```

> ⚠️ Views with GROUP BY, DISTINCT, aggregates, or JOINs are generally NOT updatable.

---

## Advantages vs Disadvantages

| Advantages                         | Disadvantages                              |
| ---------------------------------- | ------------------------------------------ |
| Security: hide sensitive columns   | Performance overhead for complex views     |
| Simplicity: hide complex joins     | Limited support for INSERT/UPDATE/DELETE   |
| Reusability: one definition, many uses | Depends on base tables (drop table = error) |
| Abstraction: separate logic from queries | Cannot have indexes directly          |

**Objective**: Use views to implement access control and reporting.

1. Create a "public view" (`vw_public_info`) showing only name, department, city — NO salary.

**Expected SQL**:
