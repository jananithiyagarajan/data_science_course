# Constraints

In SQL, constraints are rules applied to columns or tables to ensure the accuracy, reliability, and integrity of the data stored in the database.

## Types of SQL Constraints

**1. NOT NULL**

Ensures the column cannot store NULL values.

**2. UNIQUE**

Ensures no duplicate values in a column.

**3. PRIMARY KEY**

Combination of NOT NULL + UNIQUE. Identifies each row uniquely.

**4. FOREIGN KEY**

Maintains relationship between two tables; ensures **referential integrity**.

**5. CHECK**

Ensures values meet a specific condition.

**6. DEFAULT**

Applies a default value if no value is provided.

**Summary Table**

| Constraint  | Purpose                                    |
| ----------- | ------------------------------------------ |
| NOT NULL    | Value cannot be empty                      |
| UNIQUE      | No duplicates allowed                      |
| PRIMARY KEY | Unique + Not Null                          |
| FOREIGN KEY | Links tables                               |
| CHECK       | Validates conditions                       |
| DEFAULT     | Adds default value                         |
| INDEX       | Speeds up search (not a strict constraint) |

**Step 3: Practice PRIMARY KEY and FOREIGN KEY**

`FOREIGN KEY` links rows between two tables, ensuring **Referential Integrity**.

### Create a 'Profiles' Table linked to 'Users'

```sql
CREATE TABLE profiles (
    profile_id INT PRIMARY KEY,
    user_id INT NOT NULL,
    bio TEXT,
    FOREIGN KEY (user_id) REFERENCES users(user_id)
);
```

**Step 4: Practice CHECK and DEFAULT**

`CHECK` validates a condition, and `DEFAULT` provides a fallback value.

### Create a 'Products' Table

```sql
CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2) CHECK (price > 0),
    stock INT DEFAULT 0,
    category VARCHAR(50) DEFAULT 'General'
);
```

**1. Table: Customers**

```
CREATE TABLE Customers (
    CustomerID INT PRIMARY KEY,                  -- PRIMARY KEY
    FullName VARCHAR(100) NOT NULL,              -- NOT NULL
    Email VARCHAR(100) UNIQUE NOT NULL,          -- UNIQUE + NOT NULL
    Age INT CHECK (Age >= 18),                   -- CHECK Constraint
    Status VARCHAR(20) DEFAULT 'Active'          -- DEFAULT
);
```
<img width="840" height="272" alt="Screenshot from 2026-03-11 13-35-19" src="https://github.com/user-attachments/assets/2da44cd8-249c-4e6f-b5dc-e5c105c2855e" />


**2. Table: Accounts**

```
CREATE TABLE Accounts (
    AccountNo INT PRIMARY KEY,                    -- PRIMARY KEY
    CustomerID INT NOT NULL,                      -- NOT NULL
    AccountType VARCHAR(20) DEFAULT 'Savings',    -- DEFAULT
    Balance DECIMAL(10,2) CHECK (Balance >= 0),   -- CHECK
    FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)   -- FOREIGN KEY
);
```

**3. Table: Transactions**

```
CREATE TABLE Transactions (
    TxnID INT PRIMARY KEY,                           -- PRIMARY KEY
    AccountNo INT NOT NULL,                          -- NOT NULL
    Amount DECIMAL(10,2) NOT NULL CHECK (Amount > 0),-- CHECK
    TxnType VARCHAR(10) CHECK (TxnType IN ('Credit', 'Debit')), 
    FOREIGN KEY (AccountNo) REFERENCES Accounts(AccountNo)   -- FOREIGN KEY
);
```

### Task 1: Basic Constraints Setup (Easy)
**Objective**: Practice creating tables with essential constraints.

**Instructions**:
1. Create a `products` table with:
   - `product_id` — PRIMARY KEY, AUTO_INCREMENT
   - `name` — NOT NULL, max 100 chars
   - `price` — NOT NULL, CHECK (price > 0)
   - `category` — DEFAULT value 'General'
   - `stock` — CHECK (stock >= 0), DEFAULT 0
2. Insert 5 products (including one that uses default values).
3. Try to insert a product with price = -100 and observe the error.
4. Add a UNIQUE constraint on `name`.
5. Try to insert a duplicate name and observe the error.

**Expected SQL**:
```sql
CREATE TABLE products (
    product_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL UNIQUE,
    price DECIMAL(10,2) NOT NULL CHECK (price > 0),
    category VARCHAR(50) DEFAULT 'General',
    stock INT DEFAULT 0 CHECK (stock >= 0)
);

INSERT INTO products (name, price) VALUES ('Laptop', 55000);
INSERT INTO products (name, price, category, stock) VALUES ('Phone', 20000, 'Electronics', 50);

-- This should fail:

INSERT INTO products (name, price) VALUES ('Laptop', 15000); -- UNIQUE violation
```

### Task 2: Foreign Key & Referential Integrity (Medium)
**Objective**: Practice FK constraints and understand referential integrity.

**Instructions**:
1. Create `categories(cat_id, cat_name, description)` with PRIMARY KEY.
2. Create `products2(prod_id, name, price, cat_id)` with FOREIGN KEY referencing `categories`.
3. Insert 3 categories and 6 products.
4. Try to insert a product with a non-existent `cat_id` → observe FK error.
5. Try to DELETE a category that has products → observe FK error.
6. Add `ON DELETE CASCADE` and re-test deletion.

**Expected SQL**:
```sql
CREATE TABLE categories (
    cat_id INT PRIMARY KEY AUTO_INCREMENT,
    cat_name VARCHAR(50) NOT NULL,
    description VARCHAR(200)
);

CREATE TABLE products2 (
    prod_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2) CHECK (price > 0),
    cat_id INT,
    FOREIGN KEY (cat_id) REFERENCES categories(cat_id) ON DELETE CASCADE
);

-- This should fail (cat_id 999 doesn't exist):
INSERT INTO products2 (name, price, cat_id) VALUES ('Unknown Item', 100, 999);

-- With CASCADE: deleting category also deletes its products
DELETE FROM categories WHERE cat_id = 1;
```
