## 1. Numeric Data Types

Used for storing numbers.

| Data Type    | Description                  | Example    |
| ------------ | ---------------------------- | ---------- |
| INT          | Whole numbers                | 10         |
| SMALLINT     | Smaller range of integers    | 120        |
| BIGINT       | Very large integers          | 9000000000 |
| DECIMAL(p,s) | Exact numbers with precision | 25.50      |
| NUMERIC(p,s) | Same as DECIMAL              | 100.75     |
| FLOAT        | Approx numeric value         | 12.345     |
| REAL         | Approx float                 | 3.14       |

**Use cases:** salary, price, age, quantities.

**Step 1: Numeric Data Types (INT, DECIMAL, FLOAT)**

Numeric types are used for everything from IDs to financial data.

```
CREATE DATABASE datatypes_practice;
USE datatypes_practice;
```

## 2. String / Character Data Types

Used to store text or characters.

| Data Type  | Description            | Example         |
| ---------- | ---------------------- | --------------- |
| CHAR(n)    | Fixed-length string    | 'ABCD'          |
| VARCHAR(n) | Variable-length string | 'John'          |
| TEXT       | Large text data        | Notes, comments |

**Use cases:** names, emails, descriptions.

**Step 2: String / Character Data Types (CHAR, VARCHAR, TEXT)**

Understanding the difference between fixed and variable length strings.

```
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    country_code CHAR(3),      -- Fixed length (always 3 chars)
    username VARCHAR(50),     -- Variable length (up to 50 chars)
    bio TEXT                  -- For large amounts of text
);
```

## 3. Date and Time Data Types

### Task 1: Data Type Practice (Easy)
**Objective**: Choose the correct data types for real-world tables.

**Instructions**:
1. Create a `customers` table with columns for:
   - Customer ID (unique, auto-increment)
   - Full name (max 100 chars, required)
   - Email (max 150 chars, must be unique)
   - Phone (exactly 10 digits)
   - Date of birth
   - Account balance (monetary, 2 decimal places)
   - Is premium member (true/false)
   - Registration timestamp
2. Insert 5 customers with varied data.
3. Query: find customers born after 1990.
4. Query: find customers with balance > 5000.

**Expected SQL**:
```sql
CREATE TABLE customers (
    customer_id INT PRIMARY KEY AUTO_INCREMENT,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    phone CHAR(10),
    dob DATE,
    balance DECIMAL(12,2) DEFAULT 0.00,
    is_premium BOOLEAN DEFAULT FALSE,
    registered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

SELECT * FROM customers WHERE dob > '1990-01-01';
SELECT * FROM customers WHERE balance > 5000;
```

### Task 2: Date & JSON Data Types (Medium)
**Objective**: Work with date/time operations and JSON data.

1. Create an `events` table with: `event_id`, `name`, `start_date` (DATE), `start_time` (TIME), `event_dt` (DATETIME), `created_at` (TIMESTAMP).
2. Insert 5 events.
3. Find events happening this month.
4. Calculate how many days until each event from today.
5. Create a `products_json` table with a JSON column `attributes`.
6. Insert 3 products with JSON data like `{"color": "red", "size": "M", "weight": 500}`.
7. Query products where JSON `color = 'red'`.

**Expected SQL**:
```sql
CREATE TABLE events (
    event_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    start_date DATE NOT NULL,
    start_time TIME,
    event_dt DATETIME,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Days until event
SELECT name, start_date, DATEDIFF(start_date, CURDATE()) AS days_remaining
FROM events WHERE start_date > CURDATE();

-- JSON operations
CREATE TABLE products_json (
    prod_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50),
    attributes JSON
);

INSERT INTO products_json (name, attributes)
VALUES ('T-Shirt', '{"color": "red", "size": "M", "weight": 200}');

SELECT name, attributes->>'$.color' AS color
FROM products_json WHERE attributes->>'$.color' = 'red';
```

### Task 3: Type Conversion & Data Integrity Challenge (Challenge)
**Objective**: Handle type conversions and understand data type implications.

1. Create a `sales_import` table with ALL VARCHAR columns (simulating data import).
2. Insert 10 rows with mixed good and bad data (e.g., "abc" in price column).
3. Use CAST and CONVERT to transform to proper types.
4. Identify which rows fail type conversion.
5. Create a `sales_clean` table with proper data types.
6. Transfer valid data from `sales_import` to `sales_clean`.

**Expected SQL**:
```sql
CREATE TABLE sales_import (
    sale_id VARCHAR(10),
    product VARCHAR(100),
    price VARCHAR(20),     -- Could contain "55000", "N/A", "unknown"
    quantity VARCHAR(10),  -- Could contain "5", "three", NULL
    sale_date VARCHAR(20)  -- Could contain "2024-01-15", "01/15/2024", "yesterday"
);

-- Find non-numeric prices
SELECT * FROM sales_import
WHERE price NOT REGEXP '^[0-9]+(\.[0-9]+)?$';

-- Transfer valid rows
INSERT INTO sales_clean (sale_id, product, price, quantity, sale_date)
SELECT
    CAST(sale_id AS UNSIGNED),
    product,
    CAST(price AS DECIMAL(10,2)),
    CAST(quantity AS UNSIGNED),
    STR_TO_DATE(sale_date, '%Y-%m-%d')
FROM sales_import
WHERE price REGEXP '^[0-9]+(\.[0-9]+)?$'
  AND quantity REGEXP '^[0-9]+$';
```
